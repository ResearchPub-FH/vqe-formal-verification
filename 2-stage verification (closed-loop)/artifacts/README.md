# Experiment evidence index

`experiment/` is the reference run of this implementation (2026-10-27) and the
source of every result reported in the paper. Its Stage 1 record is gated by the
logical model generated by `closed_loop/logical.py` (24/24 properties, 62/62
non-vacuity queries, 12/12 mutants detected), the Dafny proofs and the Storm
checks. It was run with Python 3.12.15 and NumPy 2.5.3. To re-check it, run
`python3 experiment.py audit` on a copy of the folder (see `../README.md`);
the audit rewrites `comparison/`.

The other folders are development snapshots from earlier versions of the
implementation, kept for provenance only. They are not part of the reported
results. They reuse the same seed rule as `experiment/`, so they must not be
pooled with it, or with each other, as additional independent samples:

- `approved-experiment/`: an earlier full run, gated by a 7-property version of
  the logical model. `../audit/legacy_controller.py` preserves that version,
  and `../audit/nonvacuity_audit.py` audits this run with it. `experiment/`
  reproduces it exactly: 366/400 successes and identical probability, resource,
  contract and fault-detection results. Only the Stage 1 digests differ, and
  `experiment/`'s fault verdict vectors show INCONCLUSIVE for obligations that
  never fired.
- `development-smoke-01/`, `smoke-verified/`: small-grid integration checks.
- `primary/`: the first full integration run, before exact floating-point error
  reporting and explicit optimizer-score logging were added.
- `primary-v2/`: an intermediate full run, before incomplete-evidence
  propagation was refined to prevent cascading false state discrepancies.
- `nonvacuity-smoke-01/`: a small-grid check of the Stage 1 non-vacuity gate,
  runtime obligation counting and the DejaVu trigger cross-check.
- `nonvacuity-01/`: a full run with Storm 2.0.0 and NumPy 2.3.2. Bitwise
  reproduction needs NumPy 2.5.3 (AUDIT_REPORT F10): under 2.3.2, 102 of 400
  runs diverge, giving 373/400 successes instead of 366/400.

These snapshots have different frozen source hashes and cannot be audited with
the current implementation.
