Part 0

Why verify? A wrong energy can look right

A VQE run is usually judged by its energy curve: if it falls steadily toward a minimum, the run looks healthy. The chart takes the measured counts from one declared configuration with two runs on hardware: once with the declared Hamiltonian coefficients, and once with the YZ and XX coefficients swapped.

Both curves fall smoothly. Nothing in the plot shows that the swapped version uses the wrong operator, yet it of the iterations.

The paper injects this exact fault (coefficient_swap) into real executions.
Part 1

How the VQE runs

One two-qubit operator, one four-parameter circuit, one optimizer. The evaluation uses a single setup, listed below.

The operator

The IBM two-qubit VQE benchmark operator, written in q₁ ⊗ q₀ order. Reference minimum . A run succeeds when the selected parameter vector's energy is within of it.

The circuit

Angles come from a 16-point grid: θⱼ = 2π·zⱼ/16, with wrap-around. Each candidate is measured in three bases, one per measurement group: {ZI, ZZ}, {YZ}, {XX}, with shots each.

The shared execution model

All four verification layers come from the same execution model. Press play to step through one recorded iteration: three candidates (current, −1, +1 on one coordinate), each prepared, measured in three groups, aggregated and validated, then one commit.

The optimizer is a cyclic coordinate search: each iteration remeasures the current point and its two neighbours on one coordinate, then picks the smallest integer energy score. Ties prefer current, then −1, then +1. Success is judged by an exact-simulation oracle, which is available only because this is a simulator experiment.

Green is not enough

A property such as “whenever we aggregate, all groups are measured” is trivially true in a model that never aggregates. To rule that out, every property has reachability witnesses for its premise and a probe showing its conclusion is not automatically true.

Properties

Why a green property can still be untested

An invariant “if A then B” is satisfied by any model in which A never happens. Remove the arrow into COMPUTE_ENERGY, and R1 (“aggregation only after all groups”) stays green, because nothing is ever aggregated. The property would be vacuously true.

The verification therefore asks nuXmv three kinds of extra questions, each of which must come out as expected:

  • Witness (W): the premise is reachable, e.g. EF (state = COMPUTE_ENERGY).
  • Probe (C): the conclusion is not true everywhere on its own, e.g. EF !(terms_done = NTERMS).
  • Branch (B): every guard of the model fires somewhere it is the first match, except the defensive fallback TRUE : ABORT, which must be unreachable.
